# 第 15 章：五个实战项目

这一章把前面学过的语法组合起来。不要一次做完五个项目，按顺序推进，每个项目完成后再进入下一个。

## 项目 1：命令行计算器

详细说明：[projects/01-cli-calculator](../projects/01-cli-calculator/README.md)

**练习知识点**：输入、类型转换、条件判断、函数、错误处理。

功能要求：

- 接收两个数字。
- 接收运算符：+、-、*、/。
- 检查输入是否合法。
- 检查除数是否为 0。
- 输出计算结果。
- 允许用户连续计算，输入 q 退出。

验收标准：

- 正常计算结果正确。
- 非数字输入不会导致程序崩溃。
- 除数为 0 时给出清楚提示。
- 代码至少拆成读取输入、计算、输出三个函数。

## 项目 2：Todo 命令行管理器

详细说明：[projects/02-todo-cli](../projects/02-todo-cli/README.md)

**练习知识点**：struct、slice、map、文件、JSON、错误处理。

功能要求：

- 新增任务。
- 列出全部任务。
- 标记任务完成。
- 删除任务。
- 把任务保存到 JSON 文件。
- 程序重新启动后能恢复数据。

验收标准：

- 数据不会因为程序退出而丢失。
- 找不到任务时返回可读错误。
- JSON 文件损坏时能提示问题。

## 项目 3：日志分析器

详细说明：[projects/03-log-analyzer](../projects/03-log-analyzer/README.md)

**练习知识点**：文件读取、字符串处理、map 统计、排序、测试。

功能要求：

- 逐行读取日志文件。
- 统计总行数。
- 统计不同日志级别出现次数。
- 找出包含指定关键词的行。
- 输出统计摘要。
- 对空文件和不存在的文件进行处理。

验收标准：

- 大文件使用逐行读取，而不是一次性全部加载。
- 统计结果有测试覆盖。
- 文件错误能被正确返回。

## 项目 4：HTTP API 客户端

详细说明：[projects/04-api-client](../projects/04-api-client/README.md)

**练习知识点**：net/http、JSON、context、超时、测试。

功能要求：

- 从命令行读取 API URL。
- 设置请求超时。
- 发起 GET 请求。
- 检查 HTTP 状态码。
- 解析 JSON 响应。
- 输出摘要。
- 将错误分成网络错误、HTTP 错误和 JSON 解析错误。

验收标准：

- 不把密钥写死在源码里。
- 不忽略 HTTP 状态码。
- 关闭响应 Body。
- 测试使用 httptest，不依赖真实线上服务。

## 项目 5：并发 Worker 服务

详细说明：[projects/05-worker-service](../projects/05-worker-service/README.md)

**练习知识点**：goroutine、channel、WaitGroup、context、Mutex、测试。

功能要求：

- 接收一组任务。
- 使用固定数量的 worker 并发处理。
- 收集每个任务的成功或失败结果。
- 支持 context 取消。
- 避免多个 goroutine 无保护地修改共享 map。
- 对核心逻辑编写测试。

验收标准：

- worker 数量可配置。
- 所有 goroutine 都能正常结束。
- 取消任务后不会无限等待。
- go test -race ./... 不报告数据竞争。

## 项目推进方式

~~~mermaid
flowchart TD
    A["先写输入和输出示例"] --> B["拆出最小函数"]
    B --> C["先完成最小可运行版本"]
    C --> D["补充错误处理"]
    D --> E["增加测试"]
    E --> F["整理目录和 README"]
    F --> G{"验收通过？"}
    G -- "否" --> H["定位失败项"]
    H --> D
    G -- "是" --> I["进入下一个项目"]
~~~

## 每个项目的提交要求

- README：项目用途、运行方法、示例输入输出。
- 源码：按职责拆分，命名清晰。
- 测试：覆盖正常输入和至少一个错误场景。
- Git：完成一个可运行阶段就提交一次。
- 安全：不提交真实 API Key、Cookie、密码或个人数据。

建议先完成项目 1 和项目 2。它们能帮助你把基础语法变成真正可运行的工具。
