# 第 0 章：学习路线与学习方法

## 这一章要解决什么问题

初学编程最容易遇到的不是语法太难，而是知识点太多，不知道先学哪个。Go 的学习顺序应该从“能运行”到“能表达逻辑”，再到“能组织代码”，最后才是“能处理真实任务”。

## 学习路线图

~~~mermaid
flowchart TD
    A["安装 Go"] --> B["运行第一个程序"]
    B --> C["变量与类型"]
    C --> D["条件与循环"]
    D --> E["函数"]
    E --> F["切片与映射"]
    F --> G["结构体与方法"]
    G --> H["包与模块"]
    H --> I["接口与错误处理"]
    I --> J["文件、JSON、HTTP"]
    J --> K["并发与测试"]
    K --> L["完成实战项目"]
~~~

## 先理解四个基本概念

| 概念 | 可以先这样理解 | 例子 |
|---|---|---|
| 变量 | 一个有名字的储物格 | 用户名、计数器 |
| 条件 | 根据情况选择路线 | 如果余额足够，就付款 |
| 循环 | 重复执行一组步骤 | 逐条处理订单 |
| 函数 | 一段可以重复使用的步骤 | 计算总价 |

后面会逐渐学习更精确的定义。

## 30 天建议计划

| 时间 | 内容 | 验收结果 |
|---|---|---|
| 第 1–3 天 | 安装、Hello World、变量 | 能独立运行程序 |
| 第 4–6 天 | 条件、循环 | 能写简单流程 |
| 第 7–9 天 | 函数、数组、切片 | 能处理一组输入 |
| 第 10–12 天 | map、字符串、struct | 能组织数据 |
| 第 13–15 天 | 指针、方法、包、模块 | 能拆分代码 |
| 第 16–18 天 | 接口、泛型、错误 | 能写可复用逻辑 |
| 第 19–21 天 | 文件、JSON | 能保存和读取数据 |
| 第 22–24 天 | HTTP 客户端、服务端 | 能调用和提供 API |
| 第 25–27 天 | 并发、context | 能执行和取消任务 |
| 第 28–30 天 | 测试、项目 | 完成一个可运行项目 |

这是一条建议路线，不是考试时间表。某个概念没有真正理解，就先多做几次小练习。

## 每个知识点的练习循环

~~~mermaid
flowchart TD
    A["读一个小概念"] --> B["看一段最小代码"]
    B --> C["自己敲一遍"]
    C --> D["先预测输出"]
    D --> E["运行验证"]
    E --> F{"结果和预测一致？"}
    F -- "是" --> G["修改一个条件再运行"]
    F -- "否" --> H["读错误信息，缩小问题"]
    H --> C
    G --> I["用自己的话解释"]
    I --> J["做一道练习"]
~~~

## 初学阶段的规则

1. 不要一开始就追求复杂框架。
2. 先学标准库，再学第三方库。
3. 每次只引入一个新概念。
4. 错误信息要读完整，尤其是文件名和行号。
5. 代码能运行不代表已经理解，要能解释输入、过程和输出。

## 本章练习

**练习 0.1**：用自己的话解释变量、条件、循环和函数分别解决什么问题。

**练习 0.2**：为自己安排接下来 7 天的学习时间，每天只写一个可验收的小目标。

**验收标准**：能说出下一章要学什么，并知道如何运行教材中的示例。
